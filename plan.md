# Plan: Anti-Порожняк — система предотвращения порожних рейсов (Mangystau Hackathon MVP)

## Проблема

Внутрирегиональные грузоперевозки Мангистауской области однонаправленные:
из Актау в посёлки везут коммерческий груз, обратно машины идут пустыми.
Обычные биржи грузоперевозок ищут точное совпадение точка-в-точку и
находят ноль обратных грузов на маршрутах из посёлков в Актау.

Полный контекст, требования организаторов и найденная асимметрия
зафиксированы в `PROJECT_CONTEXT.md` (три независимых разбора идеи,
дата фиксации: 2026-08-18).

## Цель MVP

Работающий задеплоенный прототип, который за 30 часов (19-20 августа,
дедлайн 20 августа 16:00) демонстрирует:
1. LLM превращает неструктурированное сообщение в заявку на груз
2. Детерминированный скоринг находит обратный груз внутри коридора
   движения машины (не точка-в-точку)
3. Два пользователя (отправитель, перевозчик) видят синхронизированное
   состояние через реальную БД
4. Экономическое обоснование — Empty KM Saved, честно посчитанное только
   по топливу

## Ключевое архитектурное решение (по итогам premortem)

**Маршрут машины = пара (origin, destination), не многоточечная петля.**
Детур/coverage считаются через insertion-heuristic по матрице расстояний
10 узлов: `detour = dist(A,C) + dist(C,B) - dist(A,B)` для вставки груза C
на маршрут A→B.

**Цепочки («машина берёт груз до Шетпе, там меняет груз, идёт дальше»)
НЕ реализуются в коде.** Это отдельная VRP-задача, которая не влезает в
30 часов при уже плотном плане. Идея остаётся в питче как roadmap-пункт,
не как вычисляемая функция.

## Стек

React (Vite) + Leaflet → FastAPI → PostgreSQL. Без PostGIS — регион
конечный (10 узлов), матрица расстояний в JSON. Карта — только
визуализация результата.

## Данные

4 таблицы: `users`, `vehicles`, `loads`, `matches` (последняя обязана
реально существовать в БД — доказательство на защите, что матчинг не
анимация). Статусы: `OPEN → ACCEPTED → IN_TRANSIT → DELIVERED`.

`locations.json` (10 узлов) и `routes.json` (матрица расстояний) —
собрать до старта. Seed на 40 рейсов с асимметрией, включая
гарантированный набор данных под конкретный демо-сценарий (не полагаться
на случайную генерацию для момента защиты).

## Алгоритм матчинга

```
Match Score =
  40%  покрытие маршрута
  25%  минимальное отклонение (detour)
  20%  совместимость груза и типа кузова
  10%  временное окно
   5%  экономический эффект
```

Каждый score сопровождается разбивкой в UI («Почему этот груз?» —
92% маршрута, 7 км отклонение, подходит кузов, окно совпадает).

## Синхронизация состояния

HTTP-polling раз в 2 секунды. Без WebSocket. Контрольная точка: два
браузера видят одно состояние из БД к 19 августа 20:00.

## Экономика

Только топливо: `Empty KM Saved × 30 л/100км × цена дизеля`. Амортизация
и время — только текстом, не в цифре. Каждое допущение подписано в UI.

**Допущение про спрос на возвратную тару (найдено CEO-ревью).** У команды
нет подтверждённого звонка перевозчику/магазину о готовности платить за
перевозку тары/вторсырья/лома. Экономика Empty KM Saved считается честно,
но не отвечает на вопрос жюри «а кто платит за обратный груз и сколько».
Мера: в UI рядом с ценой обратного рейса — явная пометка `цена оценочная,
подтверждённых сделок нет` (как остальные demo assumptions), и на защите
проговорить границу явно: механизм подтверждён, объём реального спроса —
нет. Не заявлять больше, чем показано.

Seed данные подбираются так, чтобы главный демо-сценарий (Актау→Шетпе
кирпич → обратная тара до Жанаозена) гарантированно давал чистый
результат без случайности.

## Внешние зависимости — риски, найденные в premortem

- **LLM-вызов в момент демо** — точка отказа вне контроля (сеть,
  рейт-лимит, malformed JSON). Мера: закешировать разобранный JSON для
  точной отрепетированной демо-фразы; не полагаться на живой вызов в
  кадре на защите.
- **Render free tier cold start** — бэкенд засыпает после простоя,
  холодный старт ~30-50 сек убивает первое впечатление у судьи,
  кликающего по ссылке. Мера: прогрев live-URL и сквозной прогон именно
  по продовому адресу (не localhost) в блоке 08:00-12:00 20 августа.

## Что НЕ делаем (вычеркнуто)

Оплата, SMS/OTP-регистрация, встроенный мессенджер, рейтинги, e-накладные,
реальный GPS, мобильное приложение, погодная модель, собственная
ML-модель, PostGIS/роутинг по реальным дорогам, админка, >3 ролей,
вычисляемые многоплечевые цепочки (см. выше).
